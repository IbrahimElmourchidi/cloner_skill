The file

# src/main.py — hand-written, committed

def main() -> None:
    print("hello")


if __name__ == "__main__":
    main()

Twelve lines, and two of them are load-bearing. The if __name__ guard is the one that matters: it lets the module be imported without running, which is the difference between main.py being a program and being a file that happens to print something.

Best practice

The entry-point guard is not optional. Every Python tool and test runner imports the module to inspect it. Without the guard the import has a side effect, so the test suite prints to stdout on collection.

What breaks

Calling main() at module scope instead. The first test that imports this file hangs, and the traceback points at the import rather than at the mistake.

What fails quietly

Nothing here. That is the point of starting with a file this small — it gives every later step something that can only break loudly.

On line one

The comment above the code is not decoration. Every code block on this site names its path and says whether the file is hand-written or generated, so a reader can tell at a glance which files they are allowed to edit.

What could be better

Not fixed here, on purpose

There is no argument parsing and no exit code. Both belong in the CLI step that comes after this one, and bolting them on now would mean editing this file twice — once to exist, once to be correct.
